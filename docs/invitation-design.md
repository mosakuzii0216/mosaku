# 招待コードの設計

要件は [invitation.md](./invitation.md)。

## 表

- 招待コードの表（invitations）を1つ足す
  - コード（code）：8文字。大文字と、見間違えにくい数字だけを使う。打つときは大文字・小文字やハイフンを気にしなくていい
  - 作った人（createdById）・使った人（usedById、まだ使われていなければ空）
  - 作った日・使った日・期限（作ってから1か月）・取り消した日
- ユーザの表に、開発者の印（isDeveloper）を1つ足す。本番では、自分のユーザにだけSQLで付ける
- プレミアムかどうかは、招待の表から分かる。「使った人」に名前がある人と、開発者がプレミアム。ユーザの表には持たない。コードごとの期限も、あとでこの表に足す

## プレミアムで付くもの

- AIを使えるのは、プレミアムの人だけ。今の「Googleで登録したか」の確かめを、「プレミアムか」に変える
- AIの回数は今のまま（1人1日20回、みんな合わせた上限も同じ）。Geminiの無料枠で続ける
- 前から登録している人がほかにいれば、移すときに「招待を使った」ことにしてAIを使えるままにする（本番で人数を確かめてから）
- 招待の人だけのテーマは、営業を始めてから作る。届いたことを画面で知らせる

## コードを使う流れ（登録と一緒に使う）

1. 相手は設定の「アカウント」で、コードがあれば打ってから「Googleで登録」を押す
2. コードが打たれていたら、backendが確かめる。使えなければ理由を分けて返す（見つからない・もう使われている・期限切れ・取り消されている）
3. 使えるなら、コードを10分で消える使い捨てのCookieに預けて、Googleへ送る（今の合言葉と同じ形）
4. Googleから戻ったら
   - 前に登録したGoogle（ログイン）：コードは使わずに、今のままつなぐ。コードはまだ使える
   - 初めてのGoogle（登録）：預かったコードを、ここで使う。往復のあいだに期限切れや取り消しになっていたら、登録せずに理由を付けて戻す
   - 初めてのGoogleでコードが無い：そのまま登録する。プレミアムは付かないので、AIは使えない
5. Xでログインを足すときも、同じ形にする

## 作る・取り消す

- 設定に「招待」を足す。自分のコードの一覧（まだ・使われた・期限切れ・取り消し）と、「コードを作る」
- 作れるのはプレミアムの人だけ（招待で登録した人と開発者）。コードを打たずに登録した人が作れると、誰でもAIを開けてしまうため。まだ使われていないコードと使われたコードを合わせて3枚まで。取り消した分と期限が切れた分は数えない。開発者は上限なし
- 取り消せるのは、まだ使われていないコードだけ

## 数える

- 招待で誰かが登録するたびに、backendがログに1行出して、Cloud MonitoringがSlackへ知らせる（目安箱と同じ形）。例：「招待で1人が登録（開発者の招待は10人中3人）」
- 書き始めたか・続いているか・AIを使ったかは、アタシが出すSQLを本番に流して見る（流すのは自分）

## API

- POST /invitations：コードを作る
- GET /invitations：自分のコードの一覧と、あと何枚作れるか
- POST /invitations/:id/revoke：取り消す
- POST /invitations/check：打ったコードを確かめる
- GET /auth/google/start?invite=…：確かめたコードを預けて、Googleへ
- GET /me：プレミアムかどうか（isPremium）を足す。CLAUDE.mdの「GET /meは{ hasPasskey, hasGoogle }だけ返す」を書き換える
